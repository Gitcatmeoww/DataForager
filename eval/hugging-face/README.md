# KaggleDS: Corpus for Task-based Dataset Search

KaggleDS is a benchmark corpus for evaluating **task-driven dataset search** — retrieving relevant tables from natural-language descriptions of analytical goals (e.g., _"Analyze trends in the California real estate market over the past decade"_) rather than keyword or schema-level queries.

The corpus was introduced in the paper **"DataForager: Enabling Flexible Need-Aligned Dataset Navigation"**.

## Corpus Overview

|           | Train | Validation | Test  | Total     |
| --------- | ----- | ---------- | ----- | --------- |
| Tables    | 2,715 | 1,451      | 2,337 | **6,503** |
| Databases | 1,256 | 628        | 1,257 | **3,141** |

The corpus is derived from Kaggle datasets crawled via the Kaggle CLI in May 2024. A three-step filtering pipeline retains only (1) CSV files, (2) permissively licensed databases, and (3) databases with non-empty descriptions. Splits are partitioned at the database level to prevent schema leakage between train and test.

## Schema

Each row represents one table and contains the following fields:

### Table & Database Metadata

| Field               | Type   | Description                            |
| ------------------- | ------ | -------------------------------------- |
| `table_name`        | string | Filename of the CSV table              |
| `database_name`     | string | Name of the parent Kaggle dataset      |
| `db_description`    | string | Dataset description from Kaggle        |
| `col_num`           | int    | Number of columns                      |
| `row_num`           | int    | Number of rows                         |
| `tags`              | string | Author-provided Kaggle tags            |
| `popularity`        | float  | Total downloads (proxy for popularity) |
| `usability_rating`  | float  | Kaggle usability score                 |
| `file_size_in_byte` | int    | File size in bytes                     |
| `example_rows_md`   | string | Example rows in Markdown table format  |
| `schema_type`       | string | `normalized` or `denormalized`         |
| `table_count_type`  | string | `single_table` or `multi_table`        |

### Inferred Metadata (LLM-generated)

| Field        | Type   | Description                                                                                  |
| ------------ | ------ | -------------------------------------------------------------------------------------------- |
| `time_granu` | string | Temporal granularity (Year, Quarter, Month, Week, Day, Hour, Minute, Second)                 |
| `geo_granu`  | string | Geographic granularity (Continent, Country, State/Province, County/District, City, Zip Code) |
| `keywords`   | string | LLM-generated keywords describing the table                                                  |

### Queries

| Field              | Type          | Description                                                                                                                                |
| ------------------ | ------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `task_queries`     | string (JSON) | 3 natural-language task queries per table, generated by GPT-4o conditioned on the dataset description                                      |
| `metadata_queries` | string (JSON) | Per task query, a set of metadata filtering queries (one per metadata field), e.g., _"The dataset should have records on a monthly level"_ |

### Embeddings

| Field                           | Type          | Description                                                                           |
| ------------------------------- | ------------- | ------------------------------------------------------------------------------------- |
| `example_rows_table_name_embed` | string (JSON) | Pre-computed embedding vector (`text-embedding-3-small`) of table name + example rows |

## Query Types

The corpus pairs each table with three types of queries to support different retrieval paradigms:

- **Task queries** express analytical goals in natural language (e.g., _"Evaluate the impact of neighborhood characteristics on property prices in California"_). These are the primary queries for task-driven retrieval evaluation.

- **Metadata queries** express filtering constraints in natural language (e.g., _"The dataset should have data on at least the city level"_, _"The dataset should contain at least 2000 rows"_). These support evaluation of NL-based metadata filtering.

- **Keyword queries** are keyword-style phrases (e.g., _"real estate listings; property specifications"_) used as baselines for comparison with keyword-based retrieval.

All queries are generated by GPT-4o, conditioned on the Kaggle dataset description and table content.

## Intended Use

This corpus is intended for, but not limited to, the following use cases:

- Evaluating **task → table** retrieval systems
- Benchmarking semantic and keyword-based dataset search
- Evaluating NL-based metadata filtering and refinement
- Training dense retrieval models for dataset discovery

## Construction Details

1. **Source:** Kaggle datasets crawled via `kaggle datasets download` (May 2024)
2. **Filtering:** CSV-only → permissive license → non-empty descriptions
3. **Metadata enrichment:** Temporal and geographic granularity inferred from column headers and example rows using GPT-4o
4. **Query synthesis:** Task, metadata, and keyword queries generated by GPT-4o conditioned on dataset descriptions
5. **Splitting:** Database-level partitioning (60% train+val, 40% test; train:val = 2:1)
